# Crawl report – ViBioMIR links corpus (test crawl, 2026-10-01)

Module: `src/crawl.py` + `src/extractors/` · state: `data/cache/crawl.sqlite` · output: `data/docs/corpus-XXXXX.parquet`
The "Run summary / Per-host results / Full-crawl estimate" sections are generated by `python -m src.crawl --report <file.md>` (writes only those sections); the rest is hand-written analysis.

## TL;DR

- **Test crawl:** 5 random URLs per host for all 97 hosts (465 URLs; small hosts have fewer than 5). **437 ok (94.0%)**,
  89/97 hosts at 100%. Wall time 163 s at per-domain concurrency 4 and a 0.25 s delay, so it was limited by politeness.
  Mean text length is 2,320 chars/doc and zstd parquet takes about 1.25 KB/doc. No raw HTML is stored.
- **Lost or blocked:** `zysjonline.com` (243k URLs, 5.5% of the corpus) sits behind a Cloudflare managed JS challenge.
  `bingli/article.iiyi.com` (30.6k) return HTTP 521 for the whole site (origin down).
  `pmc-ecm-healthblog.beta.pharmacity.io` (5.3k) returns 403 from nginx (closed beta). `thaythuocvietnam.vn` (2.9k)
  redirects every article to the home page (articles removed). Together this is about **6.4% of URLs (~285k)**, which
  are probably unrecoverable without a browser or Wayback.
- **Fixed during the test:**
  - **TLS fingerprinting.** `nhathuoclongchau`, `vov`, `tamanhhospital` and others return 403 to Python's OpenSSL
    fingerprint. The default backend is now **curl_cffi** with Chrome impersonation. Its own UA must be kept: a custom UA
    that disagrees with the TLS fingerprint gets 403 again.
  - **JS cookie challenge.** `laodong.vn` serves `document.cookie="D1N=..."; reload()`. This is solved automatically.
  - **Broken HTTP/2 on some servers.** curl error 16 on `qihuangzhishu.com`; the crawler now falls back to HTTP/1.1.
  - **GBK/GB2312 pages.** These are decoded as GB18030 (18/437 docs in the test). The order of checks is header, then
    `<meta>`, then utf-8, gb18030, charset_normalizer.
- **Full crawl estimate (4.39M URLs).** With per-domain concurrency 16, a 0.05 s delay and `split_hosts: [39.net]`,
  expect **≈ 30–40 h wall**. The bottleneck is per-request latency on 120ask.com and ask.39.net, not bandwidth or CPU.
  Expect **≈ 4.1M docs and ≈ 5 GB** of parquet. The current polite defaults (4 / 0.25 s) would take about 5 days.

## Extraction quality (manual inspection)

I read the first and last paragraphs of 2–6 pages per host for the top ~25 hosts. Site-specific CSS extractors now
cover the hosts where trafilatura grabbed menus, related-link lists or author bios, or missed the content:

| host(s) | extractor | what it keeps / removes |
|---|---|---|
| 120ask.com | `ask120` | question description, plus **every doctor answer** (病情分析/指导意见) and doctor follow-ups. Removes nav, "其他类似问题", boilerplate like "以上是对…的建议", and literal escaped `<P>` markup in old answers. trafilatura returned only the nav menu on some pages |
| ask.39.net | `ask39` | question, supplementary description, **all answers**. Removes the doctor card, report link and timestamps |
| cnkang.com | `cnkang` | `.detailc` / `#endText`. Drops the "核心提示" summary, which duplicates paragraph 1 |
| familydoctor.com.cn (+ subdomains) | `familydoctor` | `#viewContent`. Drops share bar, editor and ads |
| a-hospital.com, zhongyibaodian.net | MediaWiki rule | `#mw-content-text` without TOC, breadcrumb, navboxes, "参看/市场上的…" link farms, comment box, app banner |
| zydcd.com, wujue.com | strict rules | dictionary panel / `.art-text`. A page without a body gives *empty* rather than a footer |
| youlai.cn, jbk.39.net, *.39.net articles, msdmanuals.cn | CSS rules | article body only (hashed class names are handled with `[class*=…]`) |
| nhathuoclongchau.com.vn | `longchau` | sapo box + `[data-theme-element=article]`. trafilatura sometimes returned only the pharmacist bio |
| vinmec.com, suckhoedoisong.vn, suckhoecongdongonline.vn, laodong.vn, qihuangzhishu.com | rules / post-filters | remove booking boilerplate, related-news boxes, duplicated mobile copies, site suffix in titles, download ads |
| other ~60 VN news sites | trafilatura (`favor_precision`) | output was clean on every inspected page |

General normalisation: Unicode NFC, zero-width characters removed, whitespace collapsed inside paragraphs, paragraphs
joined with `\n\n`. Consecutive or repeated duplicate paragraphs are dropped, as are paragraphs with no letters or
digits. When the `<h1>` title is repeated as the first paragraph it is removed, since it stays in `title`. Language is
decided by characters (CJK ratio, Vietnamese diacritics) with the host TLD as fallback; the test gave vi 232, zh 205
with no mislabels seen.

Residual quality notes:
- Q&A pages are short (ask.39.net about 170 chars, 120ask about 680 chars). This is the real content, not truncation.
- jb39.com disease pages contain only teaser snippets ending in "……". That is the page itself.
- a-hospital hospital-directory pages are long lists of addresses. They are valid but low value for medical QA, so
  consider filtering by title or URL in `chunk.py` or `index.py` if they hurt precision.
- The order of some cnkang paragraphs follows the source HTML, where headings sometimes come after their paragraph.

## Full-crawl plan and recommendation

Rate per politeness key = min(concurrency / mean latency, 1 / delay). Wall time ≈ the slowest key, provided the
global cap is not hit:

| key | URLs | setting | expected rate | hours |
|---|---:|---|---:|---:|
| cnkang.com | 963k | c=16, delay 0.05 | 20/s (delay-capped) | 13.4 |
| 120ask.com | 918k | **c=32**, delay 0.05 | 32/2.2 ≈ 14.5/s | 17.6 (35 h at c=16) |
| ask.39.net (split from 39.net) | 337k | **c=32**, delay 0.05 | 32/6.95 ≈ 4.6/s | 20.3 (41 h at c=16) |
| familydoctor.com.cn | 451k | c=16 | ≈ 7.5/s | 16.6 |
| other *.39.net (each its own key) | 159k | c=16 | ≈ 10/s per host | < 2 |
| zhongyibaodian.net | 147k | c=16 | ≈ 4.2/s | 9.6 |
| suckhoecongdongonline.vn | 155k | c=16 | ≈ 4.7/s | 9.0 |
| everything else | ~1.0M | c=16 | 5–20/s | < 5 each |

The aggregate is about 100 req/s at the start (about 12 MB/s download, CPU well under 6 cores), so
`global_concurrency: 160`. The expected **wall time is ≈ 20–24 h**, or ≈ 40 h without the c=32 overrides. Disk is
≈ 4.1M docs × 1.25 KB ≈ **5 GB** of parquet plus about 0.5 GB of sqlite state, which fits in the free ~22 GB.

Recommended configuration (for `configs/default.yaml` or a copy passed with `--config`):

```yaml
crawl:
  global_concurrency: 160
  per_domain_concurrency: 16
  per_domain_delay: 0.05
  split_hosts: [39.net]                       # ask.39.net is ~4x slower than the other 39.net hosts
  domain_overrides:
    120ask.com:  {concurrency: 32}
    ask.39.net:  {concurrency: 32}
```

Suggested order of operations:
1. **Vietnamese first:** `python -m src.crawl --lang vi` (738k URLs, 47 hosts). Most VN hosts finish in 1–2 h.
   suckhoecongdongonline.vn (~9 h) is the tail. The VN corpus is what the Vietnamese queries match most directly, and
   it unblocks chunking and indexing early.
2. **Chinese, in parallel:** `python -m src.crawl --lang zh` in a second process. Politeness is per domain, so the two
   processes never share a host. They safely share the sqlite (WAL) and the output dir (shard numbers are claimed with
   an atomic `os.link`). Splitting also keeps RAM down: the full target list is about 2.7 GB RSS, while each half
   needs about 1.5 GB.
3. **Watch the log** (one line every 15 s with counts per status). The crawler doubles a domain's delay on 429/503/403
   and gives up on a host for the run after 25 consecutive failures with no success. If a big host starts returning
   429s, lower its override. Stopping is safe: Ctrl-C flushes. Restarting skips final ids (`ok`, `empty`, `gone`,
   `not_html`, `redirect_home`) and retries transient failures up to `max_runs: 3` runs (`--retry-failed` for more).
4. If time is short, crawl the Q&A giants (120ask, ask.39.net) last or partially (`--limit`, or `--shard i/n` for a
   uniform id sample). They are numerous but short, about 2.6M docs at 170–680 chars.

## Known issues / not done

- **zysjonline.com (243k URLs, 5.5% of the corpus) is unrecoverable as-is** because of the Cloudflare managed
  challenge. Untested option: pass the challenge once in a real Chrome, then put `cf_clearance` plus that browser's
  exact `User-Agent` into `domain_overrides: {zysjonline.com: {cookies: {...}, headers: {...}}}` (supported by the
  crawler). The clearance is bound to IP, UA and fingerprint and expires, so this may not hold. The Wayback
  availability API had no snapshot for the URLs tried, and it rate-limits (429).
- **iiyi.com is entirely down (HTTP 521)**, 30.6k URLs. These are recorded as `http_error` and retried on later runs.
  Wayback is the only other option.
- **thaythuocvietnam.vn redirects every article to the home page**, recorded as `redirect_home` (final).
  **pmc-ecm-healthblog.beta.pharmacity.io returns 403** (closed beta site).
- robots.txt is not consulted. Politeness relies on per-domain concurrency, delay and adaptive back-off.
- `--report` estimates use registered-domain keys and ignore `split_hosts` and per-domain overrides.
- Site rules are tuned on pages from Oct 2026. If a site redesigns, its rule returns nothing and the page falls back to
  trafilatura (`method` in the state db shows which extractor ran), so watch `method` and `n_chars` per host during
  the run.
- `curl_cffi` was installed into `.venv` (`pip install curl_cffi`). It was not in the base package list; add it to the
  environment spec.
